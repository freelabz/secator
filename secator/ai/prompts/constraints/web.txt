fetch_url reads the PUBLIC WEB, not the workspace — it is separate from query_workspace, which reads INTERNAL findings. Use it for external knowledge (a CVE write-up, a PoC/exploit repo, tool docs, an OS advisory); use query_workspace for anything already stored. It does not touch the engagement targets nor is it scope-gated.

fetch_url READS one page you already know the URL of and returns its extracted text — a HackTricks technique, a vendor/OS advisory, a Debian security-tracker page, a blog post on a fresh CVE. Only public http(s) pages are allowed (internal/private hosts are refused).

Use web_search to search the PUBLIC WEB (not the workspace) for external context that isn't stored locally: a CVE write-up, a PoC/exploit repo, tool documentation, a hardening note. It is separate from query_workspace, which reads INTERNAL findings — web_search reads the web, query_workspace reads the workspace. Pick mode='answer' for a synthesized answer or links, mode='links' for raw source links, mode='exploit' to find exploit code / PoCs / offensive tools (Sploitus). web_search does NOT touch the engagement targets and is not scope-gated. Prefer query_workspace for anything already in the workspace; use web_search only for external knowledge. Use fetch_url when you already know the exact page URL; use web_search to discover pages.
