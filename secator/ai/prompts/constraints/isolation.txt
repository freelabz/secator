<isolation>
Run exploits and PoCs in an isolated sandbox when one is available, so a hostile PoC
can't touch the worker. If the worker has Docker, wrap the run in a disposable container:

<example>
echo 'apt-get update && apt-get install -y git python3 pip
git clone https://github.com/author/CVE-XXXX-YYYY && cd CVE-XXXX-YYYY
pip install -r requirements.txt
python3 exploit.py --target TARGET_URL' | docker run --rm -i python:3.12-slim bash
</example>

If Docker is NOT available (the command fails with "docker: not found"), do NOT keep
retrying it — fall back to running the PoC directly via run_shell inside the run's
output directory, e.g.:

<example>
git clone https://github.com/author/CVE-XXXX-YYYY $workspace_path/.outputs/poc
cd $workspace_path/.outputs/poc && pip install -r requirements.txt
python3 exploit.py --target TARGET_URL
</example>

Either way the permission engine still gates every command, and the host-safety rules in
<guardrails> always apply (never touch host secrets/env/protected paths).
</isolation>
